Smart Medication Support

A research prototype investigating how AI-enabled medication support can automate useful work while preserving transparency, correction, autonomy, and trust.

Context
UTS doctoral research
Role
Researcher & prototyper
Users
Older adults
Focus
Automation boundaries
Challenge System Evidence

01 / Challenge

Medication support must help without quietly taking control away.

Smart-home medication systems can recognise medicine, schedule reminders, log adherence, and alert users. The same automation can also create uncertainty: what did the system see, what action did it take, and how can a user correct it when the context changes?

The research treats automation as an interaction design problem. Instead of asking only whether a task can be automated, it asks where the system should pause, explain, confirm, or return control to the person.

02 / Prototype system

Recognition is only the start of the interaction.

01

Recognise

The system identifies medication or captures information from a camera-assisted workflow.

02

Explain

The interface makes the detected medicine, confidence, timing, and proposed action visible.

03

Confirm

The user can approve, adjust, or reject a recommendation before a consequential action.

04

Remind and guide

Visual and audio prompts support the medication routine without hiding system state.

05

Correct and recover

Logs remain understandable and actions can be changed when recognition or context is wrong.

03 / Design evidence

Trust grew when the system stayed legible and correctable.

A

Show system state

Users need to know what the system recognised, what it plans to do, and why.

B

Make control adjustable

Automation should match the task, the person, and their changing confidence.

C

Design for correction

A clear recovery path is a core part of trustworthy behaviour, not an exception state.

D

Confirm consequential actions

Human confirmation is valuable when mistakes could affect health or adherence records.

E

Respect privacy

Data collection and sharing must be understandable, limited, and aligned with user choice.

F

Adapt to context

Rigid automation cannot account for routine changes, carers, travel, or temporary needs.

04 / Research output

Automation boundaries became a design material.

The work reframes levels of automation as interaction choices that can be designed, communicated, and adjusted. The prototype is used to test how those choices affect perceived trustworthiness, acceptance, and autonomy.
